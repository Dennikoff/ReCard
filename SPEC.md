# Recards — спецификация версии 1.0

Приложение для изучения иностранных слов по карточкам с интервальным повторением.

- **Платформа:** iOS 26.0+, только iPhone, только портретная ориентация
- **Bundle ID:** `com.kharke.recards`
- **Отображаемое имя:** Recards
- **Языки интерфейса:** русский, английский
- **Сеть:** не используется вообще. Ни одного сетевого запроса в v1
- **Аккаунты, сервер, синхронизация:** отсутствуют

---

## 1. Что делает приложение

Пользователь заводит колоды слов (вручную или импортом файла) и ежедневно проходит два упражнения:

1. **Изучить новые слова** — знакомство со словами, которых он ещё не видел.
2. **Повторить** — воспроизведение уже начатых слов по расписанию, которое считает алгоритм FSRS.

Слово считается выученным, когда алгоритм назначает ему интервал больше 60 дней. Такое слово уезжает в архив и перестаёт появляться в сессиях, но остаётся видимым в колоде и может быть возвращено в ротацию вручную.

### Границы версии 1.0

**Входит:** колоды, ручное добавление слов, импорт/экспорт (CSV/TSV/JSON/буфер обмена), два режима обучения, FSRS-планировщик, проверка ответа печатью, произношение через системный синтезатор, локальные напоминания, резервная копия, настройки, две демо-колоды.

**Не входит и не обсуждается в v1:** генерация словарей через LLM, iCloud-синхронизация, iPad, macOS, распознавание текста камерой, картинки на карточках, автоматический перевод и автоподстановка транскрипции, экран статистики с графиками, монетизация, аккаунты, темы оформления, виджеты.

## 2. Модель данных

SwiftData. Все свойства имеют значения по умолчанию или опциональны, ни одного `@Attribute(.unique)` — это делает схему совместимой с CloudKit, чтобы синхронизацию можно было включить позже без миграции.

### 2.1 `Deck`

```swift
@Model
final class Deck {
    var id: UUID = UUID()
    var name: String = ""
    var emoji: String = "📘"
    var sourceLanguage: String = "de-DE"   // BCP-47, язык изучаемого слова
    var targetLanguage: String = "ru-RU"   // BCP-47, язык перевода
    var isActive: Bool = true              // участвует ли в общих сессиях
    var createdAt: Date = Date()
    var isBuiltIn: Bool = false            // пришла из бандла

    @Relationship(deleteRule: .cascade, inverse: \Word.deck)
    var words: [Word]? = []
}
```

`sourceLanguage` и `targetLanguage` **неизменяемы после создания** колоды. В UI поля языков доступны только в форме создания; на экране редактирования колоды они показаны как статичный текст. Если пользователю нужна другая пара языков — он создаёт новую колоду.

`targetLanguage` не обязан быть русским: пользователь выбирает обе стороны из списка доступных языков.

### 2.2 `Word`

```swift
@Model
final class Word {
    var id: UUID = UUID()
    var text: String = ""                  // "der Hund" — артикль является частью строки
    var translations: [String] = []        // ["собака", "пёс"] — засчитывается любой
    var transcription: String? = nil       // "/hʊnt/"
    var example: String? = nil
    var exampleTranslation: String? = nil
    var createdAt: Date = Date()
    var startedAt: Date? = nil             // момент выхода из состояния "новое"

    var deck: Deck?

    @Relationship(deleteRule: .cascade, inverse: \ReCard.word)
    var cards: [ReCard]? = []
}
```

**Артикли не разбираются приложением.** `der Hund` — это просто строка. Если пользователь записал слово с артиклем, при проверке он обязан ввести его целиком; если записал без артикля — артикль не требуется. Никакой отдельной логики родов, никакого поля `article`.

Одно и то же слово в разных колодах — **независимые записи** с независимым прогрессом. Дедупликации нет.

Редактирование текста слова **не сбрасывает прогресс**: исправление опечатки не должно стоить пользователю месяца работы.

### 2.3 `ReCard`

На каждое слово создаются **две карточки** с независимыми состояниями FSRS. Пользователь может отлично знать `собака → der Hund` и плохо `der Hund → собака`, и алгоритм обязан считать это раздельно.

**Об именовании.** Пакет `swift-fsrs` экспортирует публичные типы `Card`, `CardState`, `Rating` и `ReviewLog` — ровно те имена, которые напрашивались для моделей приложения. Чтобы избежать постоянной квалификации и путаницы, модели приложения названы иначе: `ReCard`, `ReCardState`, `ReRating`, `ReLog`.

```swift
enum CardDirection: String, Codable {
    case production   // перевод → слово, ответ печатью
    case recognition  // слово → перевод, выбор из 4 вариантов
}

enum ReCardState: String, Codable {
    case new, learning, review, relearning
}

@Model
final class ReCard {
    var id: UUID = UUID()
    var directionRaw: String = CardDirection.production.rawValue
    var isArchived: Bool = false           // выучено, вне ротации

    // Состояние FSRS
    var due: Date = Date()
    var stability: Double = 0
    var difficulty: Double = 0
    var elapsedDays: Double = 0
    var scheduledDays: Double = 0
    var learningSteps: Int = 0
    var reps: Int = 0
    var lapses: Int = 0
    var stateRaw: String = ReCardState.new.rawValue
    var lastReview: Date? = nil

    var word: Word?
}
```

`elapsedDays` и `scheduledDays` — `Double`, а не `Int`: этого требует тип пакета. `learningSteps` — индекс шага внутри фазы заучивания, тоже часть состояния алгоритма.

### 2.4 `ReLog`

Пишется при **каждом** ответе, с первого дня. В v1 нигде не читается. Причина существования: данные, которые не собраны, невозможно собрать задним числом, а статистика и персональная подстройка параметров FSRS — первое, что понадобится в v1.1. Стоимость — около 50 байт на ответ.

```swift
@Model
final class ReLog {
    var id: UUID = UUID()
    var cardID: UUID = UUID()
    var wordID: UUID = UUID()
    var gradeRaw: Int = 3                  // 1 = again, 2 = hard, 3 = good, 4 = easy
    var stateRaw: String = ""              // состояние карточки ДО ответа
    var directionRaw: String = ""
    var reviewedAt: Date = Date()
    var elapsedDays: Double = 0
    var scheduledDays: Double = 0
    var responseTimeMS: Int = 0
}
```

Связи с `ReCard` намеренно нет — только идентификаторы. Логи переживают удаление карточки.

## 3. Планировщик FSRS

### 3.1 Зависимость

Единственная внешняя зависимость проекта: [`open-spaced-repetition/swift-fsrs`](https://github.com/open-spaced-repetition/swift-fsrs) через SPM.

**Зависимость закреплена на коммит ветки `main`, а не на тег.** Последний выпущенный тег `v5.0.0` для внешнего использования непригоден: у него `FSRSParameters.init` не помечен `public`, то есть настроить алгоритм извне модуля невозможно, и типы не соответствуют `Sendable`. На `main` API полноценный, есть веса шестой версии алгоритма (`FSRSDefaults.defaultWv6`) и конформансы `Sendable`. Обновлять закреплённый коммит — осознанное действие с перезапуском тестов.

Пакет **не должен протекать** в остальной код. Вся работа с ним изолируется за собственным протоколом, работающим со снимком состояния, а не с моделью SwiftData — так логику планирования можно тестировать без хранилища:

```swift
protocol Scheduler {
    func schedule(state: CardScheduleState, grade: ReRating, now: Date) throws -> ScheduleResult
}

/// Снимок состояния карточки, не зависящий от SwiftData.
struct CardScheduleState: Equatable, Sendable {
    var due: Date
    var stability: Double
    var difficulty: Double
    var elapsedDays: Double
    var scheduledDays: Double
    var learningSteps: Int
    var reps: Int
    var lapses: Int
    var state: ReCardState
    var lastReview: Date?
}

struct ScheduleResult: Equatable, Sendable {
    // те же поля, плюс:
    var isLearned: Bool   // stability >= 60
}
```

`ReCard` умеет отдавать свой `scheduleState` и применять `ScheduleResult` обратно. Единственный файл, которому разрешён `import FSRS`, — `FSRSScheduler.swift`.

### 3.2 Маппинг ответа в оценку

FSRS ожидает четыре градации, а ввод текстом даёт бинарный результат. Маппинг:

| Что произошло | Оценка FSRS |
|---|---|
| Ответ неверный | `again` (1) |
| Ответ верный, но с одной опечаткой (расстояние = 1) | `hard` (2) |
| Ответ верный | `good` (3) |
| Ответ верный и дан быстрее чем за 3 секунды | `easy` (4) |

Время измеряется от момента появления карточки на экране до отправки ответа. Для режима `recognition` (выбор из 4) действует тот же порог.

### 3.3 Критерий «выучено»

После применения планировщика: если `stability >= 60` — карточка получает `isArchived = true` и покидает ротацию.

Слово целиком считается выученным, когда **обе** его карточки архивированы. Если обратный режим отключён в настройках — достаточно карточки `production`.

Пользователь может вернуть архивированное слово в ротацию тапом на экране колоды: `isArchived = false`, состояние FSRS сбрасывается в `new`.

## 4. Проверка введённого ответа

Самая ошибкоопасная часть приложения. Реализуется отдельным сервисом `AnswerChecker` и **обязательно покрывается юнит-тестами** — глазами эти баги не видны.

### 4.1 Нормализация

Применяется одинаково к введённой строке и к каждому ожидаемому варианту:

1. Обрезать пробелы по краям, схлопнуть внутренние последовательности пробелов в один.
2. Привести к нижнему регистру. **Регистр не проверяется** — требовать шифт на каждом немецком существительном на телефоне слишком дорого.
3. Развернуть диакритику в диграфы: `ä→ae`, `ö→oe`, `ü→ue`, `ß→ss`, `ё→е`. Правило симметрично: пользователь может ввести и `Fuß`, и `fuss` — оба нормализуются в `fuss`.

### 4.2 Сравнение

1. Нормализованный ввод совпал с любым из нормализованных ожидаемых вариантов → **верно**.
2. Иначе считается расстояние до каждого варианта. Если расстояние равно 1 **и** длина ожидаемого варианта ≥ 4 символов → **верно с опечаткой** (оценка `hard`), в фидбэке показывается правильное написание.
3. Иначе → **неверно**.

**Используется расстояние Дамерау — Левенштейна**, а не обычное Левенштейна. Разница принципиальна: перестановка двух соседних букв (`hnuger` вместо `hunger`) — самая частая описка при быстром наборе, но обычное расстояние Левенштейна оценивает её в 2 операции и ответ бы не засчитался. Дамерау считает перестановку одной операцией.

Порог опечатки не распространяется на короткие слова: для `Tag` расстояние 1 — это уже другое слово.

Точное совпадение всегда имеет приоритет над совпадением с опечаткой: сначала проверяются все варианты на равенство, и только потом считается расстояние.

### 4.3 Ожидаемые варианты по направлениям

- `production` (перевод → слово): ожидается `word.text`, ровно один вариант.
- `recognition` (слово → перевод): выбор из 4 кнопок, ввода нет.

### 4.4 Кнопка «Засчитать как верный»

На экране неверного ответа доступна кнопка, которая:

- меняет оценку с `again` на `good` и переприменяет планировщик;
- **добавляет введённый пользователем вариант в `word.translations`** (для `recognition`), чтобы синоним засчитывался впредь.

Функция существует потому, что несправедливо засчитанная ошибка — главная причина, по которой люди бросают такие приложения.

### 4.5 Настройка поля ввода

Обязательно, иначе система сломает проверку:

```swift
TextField(...)
    .textInputAutocapitalization(.never)
    .autocorrectionDisabled()
```

Панель спецсимволов над клавиатурой **не делается**. Пользователь вводит умлауты долгим нажатием или подключает системную раскладку.

## 5. Режимы обучения

### 5.1 Изучение новых слов

Берутся слова со `startedAt == nil` из активных колод, до дневного лимита новых слов.

Для каждого слова показывается лицевая сторона и две кнопки:

- **«Не знаю»** → карточка раскрывается целиком (слово, транскрипция, кнопка звука, пример с переводом). Пользователь читает и жмёт «Дальше». Слово попадает в очередь изучаемых.
- **«Знаю»** → приложение **не верит на слово** и просит напечатать. Ответ верный → обе карточки слова архивируются как выученные. Ответ неверный → слово обрабатывается как «не знаю».

В конце блока новых слов — **мини-проверка печатью** по всем словам блока, которые прошли через «не знаю». Первое воспроизведение в тот же день критично для запоминания.

По завершении у слова проставляется `startedAt`, создаются обе карточки в состоянии `new`, и к ним применяется планировщик по результатам мини-проверки.

### 5.2 Повторение

Берутся неархивированные карточки активных колод с `due <= now`, до дневного лимита повторений.

Экран карточки описан в разделе 6.3.

## 6. Сессия

### 6.1 Формирование очереди

- Сессия делится на **блоки по 20 карточек** (размер настраивается).
- Общее число карточек ограничено дневным лимитом.
- Порядок перемешивается.
- **Жёсткое правило:** карточки `production` и `recognition` одного и того же слова никогда не попадают в один блок — иначе вторая становится бесплатной подсказкой к первой.
- Если обратный режим выключен в настройках, карточки `recognition` в очередь не попадают.

### 6.2 Сохранение прогресса

Результат каждого ответа пишется в базу **немедленно** после ответа — и обновление `Card`, и запись `ReviewLog`. Никакого понятия «незавершённая сессия» не существует.

Между блоками показывается экран-передышка с двумя кнопками: **«Продолжить»** и **«Выйти»**. Выход безопасен: уже отвеченные карточки сохранили новое состояние, неотвеченные остались нетронутыми и придут в следующий раз.

Выход по крестику в середине блока требует подтверждения алертом.

### 6.3 Экран карточки: production

**До ответа.** Сверху прогресс-бар блока (`7/20`) и крестик. По центру — стеклянная карточка с переводом крупным шрифтом. Ниже поле ввода с автофокусом, клавиатура поднята сразу. Кнопка «Проверить», Enter работает через `.onSubmit`.

**Кнопки звука на этом экране нет** — она выдала бы ответ.

**После верного ответа.** Карточка окрашивается в зелёный, раскрывается полностью: слово, транскрипция, кнопка звука, пример с переводом. **Автопереход через 1.2 секунды** или по тапу в любом месте.

**После неверного ответа.** Карточка окрашивается в красный. Показывается: введённый вариант зачёркнутым, правильный ответ, транскрипция, кнопка звука, пример с переводом, кнопка «Засчитать как верный». **Автоперехода нет** — только явный тап «Дальше». Асимметрия намеренная: она заставляет посмотреть на правильное написание, а не пролистать на автомате.

Неверно отвеченная карточка **возвращается в конец текущего блока**.

### 6.4 Экран карточки: recognition

Слово крупно, рядом кнопка звука. Ниже четыре кнопки с вариантами перевода: один правильный и три отвлекающих, взятых из той же колоды.

Если в колоде меньше 4 слов — дистракторы добираются из других активных колод. Если и там недостаточно — показывается меньше вариантов, минимум 2.

### 6.5 Экран результата

По завершении сессии: число верных и неверных ответов, список слов, на которых пользователь споткнулся, с кнопкой звука у каждого.

## 7. Дневные лимиты

- **Новых слов в день** — считается количество слов с `startedAt` внутри текущих суток по всем активным колодам.
- **Повторений в день** — считается количество записей `ReviewLog` за текущие сутки, относящихся к карточкам не в состоянии `new`.

Лимиты **глобальные, а не по колодам**. С тремя колодами при лимите на колоду пользователь получил бы 15 новых слов в день и утонул.

Кнопка «учить только эту колоду» на экране конкретной колоды формирует сессию из одной колоды, но подчиняется тем же глобальным лимитам.

Когда на сегодня всё повторено, главный экран показывает «на сегодня всё, следующее повторение через N часов» и **опциональную** кнопку «Взять ещё 5 новых слов» — не навязывая, но и не запрещая.

## 8. Карта экранов

`TabView` из трёх вкладок.

### 8.1 Вкладка «Учить» (главная)

- Три числа: новых / к повторению / выучено (по активным колодам)
- Кнопка **«Изучить новые»** — неактивна, если новых нет или дневной лимит выбран
- Кнопка **«Повторить»** — неактивна, если созревших карточек нет
- Пустое состояние, если активных колод нет вообще

### 8.2 Вкладка «Колоды»

- Список колод: эмодзи, название, языковая пара, счётчики, переключатель `isActive`
- Кнопка «+» → форма создания (название, эмодзи, язык слова, язык перевода) → переход в пустую колоду
- **Экран колоды:** список слов с фильтрами «все / новые / изучаются / выучено», поиск, кнопки «Добавить слово», «Импортировать», «Экспортировать» (JSON или CSV), «Учить только эту»
- **Экран слова:** просмотр и редактирование всех полей, состояние обеих карточек, кнопка «Сбросить прогресс», кнопка «Вернуть в ротацию» для архивированных

### 8.3 Вкладка «Настройки»

См. раздел 11.

### 8.4 Навигация

- Все переходы — обычный push внутри `NavigationStack` с **родным интерактивным свайпом назад**, который следует за пальцем.
- **Навигационные бары везде системные.** Скрытие навбара (`.toolbar(.hidden)`, кастомный хедер) отключает `interactivePopGestureRecognizer` и ломает свайп. Это же правильно для Liquid Glass — система сама оформит бары новым материалом.
- **Сессия** открывается через `.fullScreenCover`: без табов, закрывается только крестиком с подтверждением. Свайпа назад в сессии нет намеренно — случайный жест не должен выкидывать из упражнения.

### 8.5 Liquid Glass

Умеренное применение. Около 80% эффекта приходит бесплатно при сборке новым SDK: системные табы, тулбары и шиты сами получают новый материал.

Осознанно применяется:

- `.glassEffect()` на карточке слова и на кнопках оценки
- `GlassEffectContainer` для группировки кнопок
- `.buttonStyle(.glass)` на основных действиях
- `.tabBarMinimizeBehavior(.onScrollDown)` для сворачивания таб-бара при скролле
- мягкий градиентный фон под стеклянной карточкой

**Не применяется:** morphing-анимации через `glassEffectID`. На экране, который пользователь видит 200 раз в день, они начинают раздражать и расходуют батарею.

## 9. Произношение

`AVSpeechSynthesizer`, оффлайн, бесплатно, без хранения аудиофайлов.

- Воспроизведение **только по нажатию кнопки звука**. Автопроизношения нет, настройки автопроизношения нет.
- Голос выбирается по `deck.sourceLanguage`. Читать английское слово немецким голосом недопустимо.
- Список доступных языков при создании колоды строится **на рантайме** из `AVSpeechSynthesisVoice.speechVoices()` — так он не врёт о том, чего в системе нет.
- Из коробки установлены `compact`-голоса. Улучшенные пользователь скачивает вручную в Настройках → Универсальный доступ → Устный контент → Голоса; программно это недоступно. В настройках приложения даём ссылку-подсказку.

## 10. Импорт и экспорт

Обе операции живут **внутри экрана колоды**. Импорт добавляет слова в текущую колоду, экспорт выгружает её.

### 10.1 Источники импорта

1. Файл через `.fileImporter` (CSV, TSV, JSON)
2. Вставка текста из буфера обмена в текстовое поле

Разделитель CSV/TSV определяется автоматически.

### 10.2 Формат CSV

UTF-8, первая строка — заголовок, обязательны только первые две колонки. Кавычки по RFC 4180.

```
word,translation,transcription,example,exampleTranslation
der Hund,собака;пёс,/hʊnt/,Der Hund bellt.,Собака лает.
```

Несколько переводов разделяются `;`.

### 10.3 Формат JSON

Он же формат резервной копии одной колоды.

```json
{
  "name": "Немецкий A1",
  "sourceLanguage": "de-DE",
  "targetLanguage": "ru-RU",
  "words": [
    {
      "word": "der Hund",
      "translations": ["собака", "пёс"],
      "transcription": "/hʊnt/",
      "example": "Der Hund bellt.",
      "exampleTranslation": "Собака лает."
    }
  ]
}
```

### 10.4 Экран «Показать формат»

Кнопка на экране импорта открывает шит с примерами из 10.2 и 10.3 и пояснением, какие поля обязательны.

### 10.5 Предпросмотр

Перед подтверждением показывается сводка: «Найдено 143 карточки, пропущено 3». Пропущенные строки можно раскрыть списком с указанием причины.

Пропускаются молча (но с учётом в сводке): строки с неверным числом колонок, пустым словом или пустым переводом, а также **дубли** — слова, уже существующие в этой колоде.

### 10.6 Резервная копия

В настройках, отдельно от поколодного экспорта: один JSON-файл со **всеми** колодами и полным состоянием карточек. Поскольку iCloud-синхронизации в v1 нет, удаление приложения означает безвозвратную потерю прогресса — это единственная страховка.

Формат: массив объектов колод из 10.3, где каждое слово дополнено блоком состояния обеих карточек.

## 12. Уведомления

Локальные, через `UNUserNotificationCenter`. Ни сервера, ни push-сертификатов.

- Одно ежедневное напоминание в заданное время: «Пора повторить N слов».
- **Разрешение запрашивается после первой завершённой сессии повторения**, а не при первом запуске. Запрос на старте приложения, смысл которого пользователь ещё не понял, получает отказ и второго шанса не даёт.
- Если созревших карточек на момент срабатывания нет — уведомление не показывается.

## 13. Первый запуск

В бандле лежат **две демо-колоды по 50 базовых слов уровня A1** с транскрипцией и примерами:

- `en_ru_a1.json` — английский → русский

Онбординга нет — приложение должно объясняться само.

Если пользователь удалил все колоды, экран «Колоды» показывает пустое состояние с кнопками «Создать колоду» и «Показать формат импорта».

## 14. Технический стек

- **Хранение:** SwiftData
- **Архитектура:** без фреймворков. `@Observable`-классы как вью-модели, SwiftData-модели как слой данных, вся логика планирования и проверки — в отдельных сервисах, не знающих про SwiftUI
- **Изоляция:** проект собран с `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, поэтому чистая логика (`AnswerChecker`, `SessionBuilder`, `Scheduler`, `FSRSScheduler`, перечисления моделей) помечена `nonisolated` — иначе её нельзя вызвать вне главного актора
- **Зависимости:** только `swift-fsrs` через SPM, закреплённый на коммит `main`
- **Локализация:** String Catalog (`Localizable.xcstrings`), русский и английский, заводится с самого начала
- **Тесты:** Swift Testing, покрываются две вещи, где ошибка невидима глазами — `AnswerChecker` (нормализация, диакритика, Левенштейн, синонимы) и `SchedulerService` (маппинг оценок, критерий архивации). UI-тестов нет

## 15. План реализации

Каждый этап заканчивается проверяемым результатом.

**Порядок изменён относительно нумерации:** этап 4 (логика и тесты) выполняется сразу после этапа 1. Он ни от какого UI не зависит, зато от него зависит всё остальное, и это единственная часть, которую можно доказать тестами, а не глазами. Строить экраны поверх непроверенного планировщика означает отлаживать две вещи одновременно.

**Этап 1. Фундамент.** ✅ *Выполнено.*

Подключить `swift-fsrs` через SPM. Создать все четыре модели SwiftData, контейнер и цель для юнит-тестов.

**Этап 12. Локализация.** ✅ *Выполнено.*
Все строки интерфейса — в `Localizable.xcstrings`, исходный язык русский, полный перевод на английский (включая интерполяции с `%lld`/`%@`). Оба языка проверены на симуляторе.

**Важно про локализацию:** SwiftUI автоматически локализует только строковые литералы, попадающие в `Text`/`Label`/`Button` как `LocalizedStringKey`. Строка, прошедшая через параметр типа `String` (`func counter(title: String)`), теряет локализацию и всегда показывается на языке исходника. Поэтому вспомогательные вью, принимающие подписи, объявляют параметры как `LocalizedStringKey`. Значения, которые не переводятся (текст слов, имена колод, сообщения `error.localizedDescription`), остаются `String` намеренно.

## 16. Решения, которые были рассмотрены и отвергнуты

Записано, чтобы не возвращаться к ним повторно.

| Решение | Почему отвергнуто |
|---|---|
| Автогенерация словарей через LLM | Требует ключа, сети и денег; риски на App Review. Отложено, архитектура импорта этому не мешает |
| Фиксированная лестница интервалов вместо FSRS | Выдумана произвольно, объективно проигрывает FSRS, который является стандартом и доступен готовым SPM-пакетом |
| Строгая проверка регистра | В немецком осмысленна, но требует шифта на каждом существительном; пользователь и так знает правило |
| Отдельное поле артикля с автодетектом | Избыточно: артикль как часть строки решает задачу проще |
| Recognition через печать перевода | Ломается о синонимы и тратит время на упражнение, которое почти ничего не тренирует |
| Одно состояние FSRS на слово | Делает статистику ложью: узнавание и воспроизведение осваиваются по-разному |
| Панель спецсимволов над клавиатурой | Пользователь решает вопрос долгим нажатием или системной раскладкой |
| Автопроизношение карточки | Раздражает при частом использовании; кнопка достаточна |
| iCloud-синхронизация | Требует опциональности всех полей и платного аккаунта; схема заранее совместима, включается позже |
| Настройка темы оформления | При Liquid Glass честнее следовать системной |
| Дедупликация слов между колодами | Создаёт неочевидное поведение: слово «исчезает» из колоды пользователя |
| Undo при удалении | Сложность не окупается; алерта-подтверждения достаточно |
| Онбординг из трёх экранов | Приложение должно объясняться само |
| iPad и ландшафтная ориентация | Не бесплатны: требуют адаптивных лейаутов и отдельной работы |
